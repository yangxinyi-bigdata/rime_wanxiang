## 概述

RIME 输入法的标点符号处理涉及多个组件和配置层面，包括字符输入控制、符号转换、和词库交互等。正确理解和配置这些组件是实现理想标点符号输入体验的关键。

## 核心组件

### Engine 流程中的三个关键组件

```yaml
engine:
  processors:
    - punctuator                    # 符号处理器，将单个字符按键直接映射为标点符号或文字
  
  segmentors:
    - punct_segmentor               # 标识符号段落，为标点符号添加 punct 标签
  
  translators:
    - punct_translator              # 配合 punct_segmentor 转换标点符号
```

#### 1. punctuator (处理器)
- **功能**: 处理标点符号的直接映射
- **作用时机**: 在输入过程中实时处理
- **配置位置**: `punctuator:` 节点

#### 2. punct_segmentor (分段器)
- **功能**: 识别并标记标点符号段落
- **作用**: 为标点符号段落添加 `punct` 标签
- **与其他组件的关系**: 为 punct_translator 提供识别基础

#### 3. punct_translator (翻译器)
- **功能**: 将标点符号输入转换为最终输出
- **工作方式**: 与 punct_segmentor 配合工作

## 配置参数详解

### speller 配置

```yaml
speller:
  alphabet: zyxwvutsrqponmlkjihgfedcbaZYXWVUTSRQPONMLKJIHGFEDCBA1234567890`,:-?!;'"()<>[]{}@#$%^&*+=_/\|~
  initials: zyxwvutsrqponmlkjihgfedcbaZYXWVUTSRQPONMLKJIHGFEDCBA`,
```

#### alphabet 参数
- **作用**: 定义可以进入输入缓存池的字符集
- **影响**: 不在 alphabet 中的字符会触发直接上屏
- **标点符号处理**: 
  - 包含在 alphabet 中：可以参与拼写组合
  - 不包含：直接上屏，无法进入缓存池

#### initials 参数
- **作用**: 定义可以作为拼写起始码的字符
- **影响**: 不在 initials 中的字符输入后会直接上屏
- **标点符号处理**:
  - 包含在 initials 中：可以启动输入缓存池
  - 不包含：无法唤起缓存池，直接上屏

### punctuator 配置

```yaml
punctuator:
  digit_separators: ""              # 数字分隔符配置
  digit_separator_action: "commit"  # 分隔符动作
  symbols:                          # 符号映射配置
    '`': [ '`', '```' ]
    ',': [ '，', '、' ]
    '"': { pair: [ '"', '"' ] }
  half_shape:                       # 半角状态下的映射
    '`': [ '`', '```' ]
    ',': [ '，', '、' ]
    '"': { pair: [ '"', '"' ] }
  full_shape:                       # 全角状态下的映射
    '`': [ '`', '```' ]
    ',': [ '，', '、' ]
    '"': { pair: [ '"', '"' ] }
```

#### 映射类型详解

1. **直接映射**
```yaml
'.': '。'
```
- 效果：输入 `.` 直接输出 `。`
- 特点：自动上屏，无候选项

2. **多选映射**
```yaml
'/': [ '/', '÷' ]
```
- 效果：输入 `/` 显示候选项列表
- 特点：可选择不同的符号

3. **提交映射**
```yaml
' ': { commit: '　' }
```
- 效果：输入空格直接提交全角空格
- 特点：立即上屏，不显示候选项

4. **配对映射**
```yaml
'"': { pair: [ '"', '"' ] }
```
- 效果：自动配对中文引号
- 特点：第一次输入左引号，第二次输入右引号

## 标点符号在缓存池中的处理机制

### 1. 输入字符的判定流程

```
输入字符 → 检查 alphabet → 检查 initials → 决定处理方式
```

#### 判定矩阵

| 在 alphabet 中 | 在 initials 中 | 处理方式 |
|----------------|----------------|----------|
| ✓ | ✓ | 可进入缓存池，可作为起始码 |
| ✓ | ✗ | 可进入缓存池，但不能作为起始码 |
| ✗ | ✓ | 直接上屏（alphabet 优先） |
| ✗ | ✗ | 直接上屏 |

### 2. 标点符号与词库的交互

#### 词库配置（zh_dicts_pro/punch.dict.yaml）
```yaml
name: punch
version: "20250627"
sort: by_weight
...
,	,	99
.	.	99
```

**作用机制**:
- 当标点符号被标记为 `abc` 标签时
- script_translator 可以处理这些标点符号
- 允许标点符号参与词汇组合和候选

### 3. 缓存池处理策略

要让标点符号能够在缓存池中正常组词和识别，需要满足：

1. **基础条件**
   - 标点符号必须在 `alphabet` 中
   - 如需作为输入起始，还需在 `initials` 中

2. **词库支持**
   - 在相应词库中定义标点符号条目
   - 设置合适的权重

3. **标签配置**
   - 确保标点符号能够获得正确的标签（通常是 `abc` 或 `punct`）

## 实战配置示例

### 示例1：逗号的完整组词支持

```yaml
# speller 配置
speller:
  alphabet: "abcdefghijklmnopqrstuvwxyz,"
  initials: "abcdefghijklmnopqrstuvwxyz,"

# punctuator 配置
punctuator:
  half_shape:
    ',': [ '，', '、' ]

# 词库配置 (zh_dicts_pro/punch.dict.yaml)
,	,	99
```

**效果**: 逗号可以进入缓存池，可以作为起始码，提供多个候选项，支持词汇组合。

### 示例2：句号的直接映射

```yaml
# speller 配置（不包含句号）
speller:
  alphabet: "abcdefghijklmnopqrstuvwxyz"
  initials: "abcdefghijklmnopqrstuvwxyz"

# punctuator 配置
punctuator:
  half_shape:
    '.': '。'
```

**效果**: 句号直接上屏，不进入缓存池，不参与组词。

### 示例3：引号的配对处理

```yaml
# speller 配置
speller:
  alphabet: "abcdefghijklmnopqrstuvwxyz\""
  initials: "abcdefghijklmnopqrstuvwxyz"

# punctuator 配置
punctuator:
  half_shape:
    '"': { pair: [ '"', '"' ] }
```

**效果**: 引号可以进入缓存池，自动配对，第一次输入左引号，第二次输入右引号。

## 故障排除

### 常见问题及解决方案

#### 1. 标点符号无法进入缓存池
**症状**: 输入标点符号直接上屏，无法与其他字符组合
**原因**: 标点符号不在 `alphabet` 中
**解决**: 将标点符号添加到 `speller.alphabet` 中

#### 2. 标点符号无法作为输入起始
**症状**: 单独输入标点符号时无法唤起候选框
**原因**: 标点符号不在 `initials` 中
**解决**: 将标点符号添加到 `speller.initials` 中

#### 3. 标点符号映射不生效
**症状**: 输入标点符号时显示英文符号而非中文符号
**原因**: 
- punctuator 配置有误
- 输入法状态问题（半角/全角）
**解决**: 
- 检查 `punctuator` 配置语法
- 确认当前输入法状态
- 检查配置文件编码

#### 4. 标点符号候选项异常
**症状**: 标点符号显示多个重复候选项或候选项顺序错误
**原因**: 
- 多个配置源冲突
- 词库权重设置问题
**解决**: 
- 检查 symbols、half_shape、full_shape 配置一致性
- 调整词库中标点符号的权重

#### 5. 配对标点符号失效
**症状**: pair 配置的标点符号无法正常配对
**原因**: 
- pair 语法错误
- 状态追踪问题
**解决**: 
- 检查 pair 配置语法：`{ pair: [ '左', '右' ] }`
- 重新部署配置文件

## 总结

RIME 标点符号的配置涉及多个层面的协调配合：

1. **speller 层面**: 控制字符是否能进入缓存池和作为起始码
2. **punctuator 层面**: 控制标点符号的具体映射和转换
3. **词库层面**: 控制标点符号是否能参与词汇组合
4. **引擎层面**: 通过 processors、segmentors、translators 协调处理流程

理解这些层面的相互关系和配置原理，是实现理想标点符号输入体验的关键。通过系统的测试和配置，可以让 RIME 输入法的标点符号功能达到最佳状态。
