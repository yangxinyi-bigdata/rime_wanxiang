# Rime 搜索模式退出机制分析

## 概述
在Rime输入法中实现搜索模式时，需要考虑各种可能导致搜索模式退出的情况，确保用户体验的一致性和逻辑的完整性。

## 主动退出搜索模式的情况

### 1. 用户主动退出
- **已完成: 再次按下搜索快捷键**: （如 Ctrl+F）
  - 用户想要退出搜索模式
  - 应该清除搜索状态，恢复正常输入

- **已完成: 按下 Escape 键**
  - 通用的取消操作
  - 应该退出搜索模式并清除搜索状态
  - 这个倒是，如果用户在搜索模式中按下了 ESC 键, 但是没有获得想要的结果, 会挺沮丧的.

- **已完成: 拦截BackSpace按键**变成删除搜索字符串


- **已完成: 选词通知中触发, 如果在搜索模式中,则退出搜索模式**

## 特殊情况处理

### 8. 搜索无结果
- **输入的字符串在当前输入中找不到匹配**
  - 是否立即退出搜索模式？
  - 还是保持搜索状态等待用户后续操作？
  - 没搜索到的话应该不反应,将输入的字母清空.

搜索无结果状态下如何处理? 
当内容是`wo vi dk ni de`, 但是搜索了y, 应该在搜索模式当中显示y,但是光标不移动.
yi也是不移动,没搜索到.
用户这时候可以删除键删除搜索内容, 或者退出搜索模式.

这个地方关键: 我之前是在lua/baidu_filter.lua里面设置的, 因为这个地方比较靠后.
如果放在前边, 又会被后面的很多处理prompt的地方覆盖, 所以统一放在这个地方.

为什么没有搜索到的时候, prompt没有更新呢? 
因为搜索到的时候, segment 变化,导致重新分词,重新触发了, 从seg到trans到filter. 所以baidu_filter更新了prompt.
但是如果没有搜索到,则没有重新触发,自然就没有变化.
所以应该在这里直接添加。

## 实现建议

### 优先级分类

**高优先级（必须处理）：**
1. 用户主动退出（Ctrl+F, Escape）
2. 选词操作（空格、数字键、回车）
3. 输入内容变化（删除、清空）
4. 应用失去焦点

**中优先级（建议处理）：**
1. 光标移动操作
2. 输入法状态切换
3. 搜索无结果情况

**低优先级（可选处理）：**
1. 特殊功能键组合
2. 窗口状态变化

### 检测方法

1. **在 processor 中检测键盘事件**
   - 监听特定按键
   - 判断是否应该退出搜索模式

2. **监听 context 状态变化**
   - composition 是否为空
   - input 内容是否发生变化
   - 光标位置是否改变

3. **设置搜索模式超时**
   - 可选：设置搜索模式自动超时
   - 避免用户忘记退出搜索模式

### 状态管理

建议使用以下属性来管理搜索状态：
- `search_move`: 是否处于搜索模式
- `search_move_str`: 当前搜索字符串
- `search_original_input`: 进入搜索模式时的原始输入
- `search_original_caret_pos`: 进入搜索模式时的光标位置

这样可以在需要时恢复到搜索前的状态。
